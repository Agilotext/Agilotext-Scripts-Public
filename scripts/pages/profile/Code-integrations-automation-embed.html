Générez votre clé d'automatisation
Cette clé permet à Make, Zapier ou n8n de demander une transcription à Agilotext en votre nom, à partir d'une URL publique vers le fichier audio (l'audio n'est pas envoyé en pièce jointe dans l'appel API).

Configurez votre scénario

Dans votre outil d'automatisation (Make, Zapier ou n8n), créez un module HTTP avec ces paramètres :
📍 URL de l'API : https://api.agilotext.com/api/v1/sendFromAutomation Cliquez ou appuyez sur Entrée / Espace pour copier
📍 Méthode HTTP : POST POST sert à envoyer ces paramètres dans le corps de la requête (GET, lui, est en principe réservé à la lecture, sans corps applicatif ici).
📍 Type de contenu (Body type) : application/x-www-form-urlencoded Les champs username, automationToken et url doivent être envoyés en paires clé=valeur encodées (URL-encoded), pas en multipart.
Postman : utilisez Body → x-www-form-urlencoded, pas form-data. Le multipart peut provoquer « Requested parameter is missing » alors que les champs sont remplis.
📍 Paramètres à envoyer (Fields / Body Parameters) :
username
votre email L'adresse email de votre compte Agilotext
automationToken
la clé générée ci-dessus La clé d'automatisation que vous avez générée dans la section précédente (commence par auto_)
url
lien vers votre fichier audio (obligatoire) URL publique, directement téléchargeable (pas une page web intermédiaire), pointant vers le fichier audio ou la vidéo source. Le serveur Agilotext télécharge ce fichier depuis cette URL : l'hébergeur doit l'autoriser (Drive, Dropbox, lien signé, CDN, etc.). Exemple dans Make : {{N.webContentLink}} — remplacez N par le numéro du module dans votre scénario.
💡 Dans Make / n8n : Make : module HTTP, envoyez les clés ci-dessus comme champs de formulaire en application/x-www-form-urlencoded (pas en form-data / multipart). n8n : nœud HTTP Request, Body Content Type : Form Urlencoded, puis les trois paires clé/valeur.
Réponse JSON : en cas de succès, le corps contient "status": "OK" et un tableau jobIdList (identifiant(s) du job). Sinon "status": "KO" et un errorMessage. Vérifiez toujours ce JSON, pas seul le code HTTP (200 peut masquer une erreur logique).
Exemple PowerShell : 
Invoke-RestMethod -Method POST `
  -Uri "https://api.agilotext.com/api/v1/sendFromAutomation" `
  -Body @{
    username = "votre@email.fr"
    automationToken = "auto_xxxxxxxx"
    url = "https://exemple.com/fichier.mp3"
  }
Avec une table de hachage -Body @{ ... }, Windows PowerShell 5.1 et PowerShell 7 envoient en général du application/x-www-form-urlencoded, comme dans les tests internes.
Exemple curl : 
curl -X POST "https://api.agilotext.com/api/v1/sendFromAutomation" \
  -H "Content-Type: application/x-www-form-urlencoded" \
  --data-urlencode "username=votre@email.fr" \
  --data-urlencode "automationToken=auto_xxxxxxxx" \
  --data-urlencode "url=https://exemple.com/fichier.mp3"

Optionnel : Recevoir les transcriptions automatiquement

Configurez un webhook pour recevoir vos transcriptions dès qu'elles sont prêtes. Agilotext enverra automatiquement les fichiers PDF (transcriptions et résumés) à votre outil d'automatisation.
📥 Voir les données reçues par le webhook
username
Votre adresse email Agilotext
jobId
Identifiant unique de la transcription (ex: 1000005758)
agilotextType
Type de fichier : TRANSCRIPT (transcription) ou SUMMARY (résumé)
filename
Nom du fichier PDF (ex: reunion_summary.pdf)
fileUrl
URL sécurisée pour télécharger le fichier PDF. Utilisez cette URL dans un module HTTP GET pour récupérer le fichier.
dateTime
Date et heure de création (fuseau indiqué dans la chaîne, souvent UTC+2 en exemple ; ex. : 05/05/25 14:53 UTC+02)
Choix de l'outil :
Collez l'URL fournie par votre outil (Make, Zapier, n8n…). Longueur maximale enregistrée : 512 caractères (conforme au stockage côté Agilotext). Sur Make, une URL peut expirer (erreur 410) : recréez le module Webhooks et mettez à jour l'URL ici.
